Milestone 4

Sprint 2 Report - NirogPath Healthcare Hub

This report includes the detailed documentation of the changes made based on the user feedback collected from the previous sprint (Sprint 1 / Milestone 3). Visual proofs are included as UI components, and automated tests have been written and executed for the new APIs and updated endpoints. It covers test setup design, input and output verification, edge-case bugs identified during testing, fixes applied, and post-testing architectural improvements.

Changes Made Based on User Feedback

RAG-Based AI Prescription & Health Assistant

Feedback addressed: Patients reported that while the platform stored prescription records, they frequently had follow-up questions regarding medication side effects, food instructions, and general health precautions that were not stored in database records.

What changed: The patient chatbot assistant was upgraded from a simple data lookup to a full Retrieval-Augmented Generation (RAG) architecture. A comprehensive health knowledge base was compiled covering medication timing guidelines, dietary precautions, cancellation policies, OPD consultation procedures, and FAQ documentation.

A vector retriever searches this knowledge base on every query. The top three most semantically relevant chunks are retrieved and injected into the AI system prompt alongside live prescription data. This allows the assistant to answer both prescription-specific questions and general health/policy questions accurately.

Files changed:

  • backend/routes/rx_qa.py — Updated endpoint to query RAG retriever and build augmented system prompt.
  • backend/config.py — Vector retriever integration & knowledge base loader.
  • frontend/src/components/nirog/PrescriptionQAModal.jsx — Patient prescription AI assistant modal.
  • requirements.txt — Added dependencies for text embeddings and vector indexing.

AI Smart Doctor & Specialty Recommender

Feedback addressed: Patients found browsing through multiple specialties, hospital listings, and doctor profiles overwhelming when unsure which specialist to select for their specific symptoms.

What changed: An AI Recommendation step was added to the appointment booking wizard. On this step, the patient enters their symptom description in plain language along with their budget and preferred city. This is sent to the backend endpoint POST /api/ai/recommend.

The backend queries the live doctor catalogue, constructs a prompt context, and invokes the AI model to recommend the best matching doctor, specialty, hospital, and consultation slot, complete with a one-sentence reasoning. The full database objects are attached to the response so the frontend can pre-select all fields in a single click ("Use this recommendation").

Edge cases are handled explicitly: non-medical queries return HTTP 400 with helpful guidance, and budget/capacity constraint warnings are included if applicable.

Files changed:

  • backend/routes/search.py — Added new AI recommendation endpoint at /api/ai/recommend.
  • frontend/src/pages/BookingFlow.jsx — Inserted AI Recommendation step into the booking wizard.
  • frontend/src/lib/api.js — Added api.recommendDoctor() service method.

Doctor & Receptionist OPD Queue Review Assistant

Feedback addressed: Doctors and clinic receptionists wanted a way to quickly identify high-priority or urgent patients in the OPD queue without opening every patient profile manually.

What changed: A new endpoint GET /api/doctor/bookings/{id}/review was implemented for doctors and receptionists. When opening a patient's booking detail, an AI Review Assistant automatically generates a structured summary with three fields: a 1-sentence booking overview, a list of urgency/clinical warning flags (e.g. "Patient reporting severe fever with elevated pulse"), and a recommended next action starting with an action verb.

In the frontend, flags render as amber warning banners and suggestions as blue action prompts. If the AI call fails for any reason, the page degrades gracefully without breaking the doctor dashboard.

Files changed:

  • backend/routes/doctor_settings.py — Added AI queue review endpoint.
  • frontend/src/pages/DoctorDashboard.jsx — Added AI Queue Review Card component.
  • frontend/src/components/nirog/UrgencyChip.jsx — Visual urgency chip component.

Post Testing Improvements

1. Doctor Specialty Auto-Swap in AI Recommender:

Testing revealed that the AI model occasionally selected a General Physician even for specific pediatric or dermatological symptom inputs. The backend was updated to validate the selected doctor's specialty against symptom keywords, automatically swapping to the correct specialist if a mismatch occurs before returning the recommendation.

2. Doctor UUID Pre-Validation Before Database Lookup:

The AI recommendation endpoint originally performed direct dictionary lookups on doctor IDs. When the AI returned a hallucinated ID not present in the database, an uncaught StopIteration exception caused an HTTP 500 error. An explicit validation step was added to return HTTP 503 with a clean error message.

3. Booking Reference Inclusion in AI Review Context:

Testing showed that the AI Queue Review prompt builder was omitting the booking reference ID string from the context payload. The prompt constructor was updated to prepend the booking reference ID on line 1, ensuring it appears in the generated summary.

4. Multi-Chunk RAG Joining:

The initial prompt generator for the prescription assistant was indexing only retrieved_chunks[0]. Testing caught this truncation. The code was updated to join all top-3 retrieved knowledge chunks with numbered headers.

5. Relevance Guard for Non-Medical Queries:

Early testing showed the recommender attempting to answer non-medical questions (e.g. general trivia). Added a relevance classification check in POST /api/ai/recommend to reject non-health queries with HTTP 400 before database calls.
